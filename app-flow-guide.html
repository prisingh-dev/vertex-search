🧱 Shared Base: Step<T>
Every step in every pipeline extends the same abstract Step<T> base which automatically:
  • Starts a latency timer on entry
  • Calls InnerHandle(context) — your logic
  • Logs elapsed time (⚠️ Warning if > 500ms)
  • Delegates to NextStep.Handle(context)

Search API — Step by Step
POST /api/v1/search · Full Vertex AI Retail keyword search
Example Request POST /api/v1/search — {"query":"running shoes","visitorId":"user-123","pageSize":10,"orderBy":"price_low_to_high","facetKeys":["color","brand"],"storeId":"store-042"}
1
HTTP Request arrives at SearchController
ASP.NET Core deserialises the JSON body into KeywordSearchRequest. Controller creates a SearchContext and fires the pipeline: 
var context = new SearchContext { ApiRequest = request };
return _stepService.Execute(context).ApiResponse!;
2
ValidateRequestStep Guard — fails fast
  • query non-blank → else 400
  • visitorId non-blank → else 400
  • pageSize between 1–100 → else 400
  • offset ≥ 0 → else 400
  • storeId — optional, no validation (invalid values return a GCP error)

StoreId — Store-Scoped Search NEW
Scope product results to a specific physical store via Vertex AI PlaceId
🏪 What it does
Adding storeId to the request tells Vertex AI to return only products available at that specific store location. Without it, results come from the entire catalog. 
{
  "query": "milk",
  "visitorId": "user-123",
  "storeId": "store-042"  ← optional
}
⚙️ How it maps through the code
LayerChange
KeywordSearchRequest.cspublic string? StoreId { get; set; }
SearchRequestMapper.csrequest.PlaceId = api.StoreId (conditional)
VertexSearchApi.csprojSDK bumped to 2.16.0 — PlaceId not in older version
Why the SDK upgrade? SearchRequest.PlaceId did not exist in the previous SDK version. Upgrading to 2.16.0 resolved the compile error and unlocks this field.
